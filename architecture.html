🛒 AI Shopping Agent — Architecture

Streamlit UI → LangGraph ReAct agent → tools → SQLite & Groq LLMs. Data flow is top to bottom.

Presentation Layer

Shopper (Browser)

chat & image upload

Types requests ("i want coffee"), uploads product photos, confirms orders.

Streamlit App

app.py

Chat UI + image uploader. Holds st.session_state.messages and a per-session session_id (uuid). Calls set_session_id() then agent.invoke().

▼messages + session_id

Agent Layer

LangGraph ReAct Agent

shopping_agent.py · create_react_agent()

System prompt defines flows: Image Search, Browsing, Browsing by Category, Ordering, Order History. Reasons over the conversation and decides which tool to call. recursion_limit = 50

▼tool calls

Tool Layer @tool

search_products()

Keyword search over name/description/category. Ratings attached, sorted best-first.

list_categories()

All categories with product counts.

list_products_by_category()

Every product in a category, ratings attached, best-first.

top_rated_by_category()

Highest-rated product per category (tie-break by reviews).

get_rating()

Single product's average rating & review count.

checkout()

Writes an order (with session_id) to the DB, returns confirmation.

get_orders()

Returns orders for the current session_id only, with total.

describe_product_image()

Sends uploaded image to vision LLM, extracts search keywords & organic flag.

Session context

contextvars holds the active session_id so tools scope orders without the LLM passing it.

▼SQL queries / API calls

Data Layer

reviews_api.py

get_product_rating() · get_ratings_for_products()

Aggregates ratings from the reviews table (AVG, COUNT).

SQLite — store.db

setup_db.py builds & migrates schema

Tables: products, reviews, orders (with session_id column).

How the agent answers — the ReAct loop

The AI alternates between thinking and acting, checking each result before deciding its next move. It repeats until it has enough to reply.

💬

1. Understand

Read your message and figure out your intent (browse? order? photo? order history?).

→
🧠

2. Think & choose a tool

Guided by its instruction sheet, decide which tool (drawer) to open — or that no tool is needed.

→
🔧

3. Act

Call the tool (e.g. search_products), which runs a real query on the database.

→
👀

4. Look at result

Read the real data returned. Enough to answer? If not, loop back and use another tool.

→
✅

5. Answer

Write the friendly reply from real facts — never guessed.

↺ repeat Steps 2–4 loop as many times as needed (LangGraph allows up to 50) before step 5.

Example — you type: "i want coffee"

  1. Understand: this is a product request, not an order.
  2. Think: "describes a product → use search."
  3. Act: search_products(query="coffee")
  4. Result: [Organic Ethiopian Coffee $16.99 ★4.75, Dark Roast Espresso $14.49 ★4.0] — enough to answer.
  5. Answer: formats the numbered list and asks if you'd like to order.
Presentation Agent Tools Data External (Groq API)
Typical flow. A shopper message goes from app.py to the LangGraph agent, which calls one or more tools. Product/rating tools read store.db (via reviews_api.py for aggregation); describe_product_image calls the Groq vision model; checkout and get_orders read/write the orders table scoped to the session. The agent's final reply is rendered back in the chat.
